# 이상탐지가 처음인 사람에게 설명하기

[README](../README.md) · [전체 구조](ARCHITECTURE.md) · [학습 가이드](LEARNING_GUIDE.md) · [실험 기록](EXPERIMENTS.md)

이 문서는 **이상탐지를 처음 접하는 스터디원이나 친구에게 이 프로젝트를 설명하려는 사람**을 위한 참고 자료입니다.
어떤 예시로 시작하고, 어떤 그림과 코드를 함께 보면 좋을지 순서대로 정리했습니다.
상대방이 알고 있는 내용에 맞춰 필요한 부분만 골라 설명해도 됩니다.

## 먼저 전체 그림부터

처음부터 모델 구조나 수식을 나열하기보다, 이 프로젝트가 풀려는 질문으로 시작해 보세요.

> 정상 부품 사진은 많이 있는데, 불량 사진은 충분하지 않다면 어떻게 검사를 시작할 수 있을까요?

이 프로젝트에서는 정상 사진을 복원하는 연습을 시킨 뒤,
새 사진의 복원 오차를 이용해 이상 여부를 판단합니다.
**정상 예시 → 복원 학습 → 새 이미지의 점수 → 임계값 판정 → 틀린 사례 확인** 순서만 먼저 전달해도 좋습니다.
다만 정상만 학습했다고 모든 불량을 찾을 수 있는 것은 아니라는 점도 뒤에서 함께 살펴봅니다.

## 함께 볼 자료 준비하기

코드를 실행하지 않고 설명할 때는 저장소에 포함된
[복원 비교 그림](assets/sample_reconstruction.png),
[점수 히스토그램](assets/score_histogram.png),
[기준 실험 결과](EXPERIMENTS.md#reference-run)를 사용하면 됩니다.
이 자료는 미리 실행해 둔 한 실험의 결과입니다.

직접 만든 결과를 함께 보고 싶다면 [README](../README.md)의 설치를 마친 뒤 실행하세요.

```bash
python run_pipeline.py --quiet-scores
```

학습 코드가 동작하는 과정만 확인하려면 `--smoke-test`로 시작할 수 있습니다.
짧게 학습한 smoke 결과와 기본 15 epoch 결과는 성능이 다를 수 있습니다.

## 1. 사진이 다르면 모두 불량일까?

함께 볼 자료: [복원 그림의 Original 열](assets/sample_reconstruction.png), [부품 생성 코드](../src/generate_dataset.py).

먼저 정상 부품과 스크래치·구멍 누락이 있는 부품을 비교해 보세요.
이어서 “같은 정상 부품을 조금 어둡게 찍거나 옆으로 옮겨 찍으면 불량일까?”라고 물어봅니다.
이 프로젝트에서는 작은 밝기·위치·회전 차이를 **정상 편차**로 취급합니다.

여기서 전달할 핵심은 **사진의 차이와 제품의 결함은 같은 뜻이 아니라는 것**입니다.
이상탐지 모델이 구분해야 하는 것은 정상 촬영 조건의 차이와 실제 결함입니다.

## 2. 정상 사진으로 무엇을 연습할까?

함께 볼 자료: [복원 비교 그림](assets/sample_reconstruction.png), [모델](../src/model.py), [학습 코드](../src/train.py).

AutoEncoder는 입력 이미지를 작은 표현으로 압축했다가 다시 복원하는 모델이라고 설명합니다.
복원 그림의 Original과 Reconstruction을 나란히 보면서,
원본과 비슷하게 복원하도록 모델 내부의 숫자, 즉 가중치를 바꾸는 과정이 학습이라고 연결하세요.
학습의 정답은 “정상”이라는 단어가 아니라 **입력 이미지 자체**입니다.

PyTorch가 처음이라면 이 설명과 그림부터 보고,
코드가 궁금해졌을 때 `zero_grad → forward → loss → backward → step`을 따라가면 됩니다.
Tensor는 이미지를 담은 숫자 배열, Batch는 여러 이미지를 묶은 것이라고 소개할 수 있습니다.
`[B,3,128,128]`은 이미지 B장, RGB 3채널, 높이와 너비가 각각 128이라는 뜻입니다.

함께 확인할 질문: “학습이 끝난 뒤 새 사진을 검사할 때도 가중치를 바꿔야 할까요?”

## 3. 복원 오차가 어떻게 판정으로 이어질까?

함께 볼 자료: [점수 히스토그램](assets/score_histogram.png),
[점수 계산](../src/inference.py), [임계값 계산](../src/threshold.py).

원본과 복원 이미지의 픽셀 차이를 제곱한 뒤 평균내면 이미지 한 장의 점수가 됩니다.
이 프로젝트에서는 이 MSE를 anomaly score로 사용합니다.
배치 전체를 한꺼번에 평균내는 것이 아니라, 각 이미지의 채널·높이·너비를 평균내 점수 하나씩을 만듭니다.

점수만으로는 정상/불량이 정해지지 않으므로 경계인 **임계값(threshold)**을 둡니다.
정상 validation 점수를 작은 순서로 놓고 약 95% 지점의 값을 경계로 사용합니다.
새 이미지의 점수가 경계보다 크면 불량, 같거나 작으면 정상으로 판정합니다.

히스토그램에서는 두 분포가 겹치는 구간을 함께 찾아보세요.
경계를 옮겨도 두 분포를 완벽하게 나눌 수 없는 경우가 있다는 점을 설명하기 좋습니다.
임계값을 정할 때는 불량 test 정답을 사용하지 않습니다.

함께 확인할 질문: “95 percentile이면 앞으로 들어오는 정상도 정확히 5%씩 오검할까요?”

## 4. 모델이 틀린 사례에서는 무엇을 배울까?

함께 볼 자료: [기준 실험](EXPERIMENTS.md#reference-run), [복원 비교](assets/sample_reconstruction.png).

처음에는 약어보다 상황으로 설명해 보세요.
정상 제품을 불량이라고 하는 것이 **오검(FP)**,
불량 제품을 정상이라고 통과시키는 것이 **미검(FN)**입니다.
이 프로젝트에서는 불량을 positive로 정의합니다.

기준 실험의 Accuracy는 79%였지만, 구멍 누락 25장은 모두 놓쳤습니다.
복원 그림에서 모델이 구멍이 누락된 상태까지 그대로 복원하는 사례를 함께 찾으세요.
정상을 잘 복원하는 능력이 모든 결함을 찾아내는 능력으로 바로 이어지지는 않습니다.

함께 확인할 질문: “전체 정답률 하나만 보면 어떤 실패를 놓치게 될까요?”

## 5. 정상인데도 점수가 커지는 이유는 무엇일까?

함께 볼 자료: [정상 편차 그래프](assets/normal_variation.png), [실험 해석](EXPERIMENTS.md#reference-run).

이번에는 결함을 추가하지 않은 정상 사진을 봅니다.
모델과 임계값을 그대로 둔 채 같은 사진의 밝기·위치·회전만 바꾼 실험입니다.
원래 사진에 있던 편차에 **추가로** 적용한 변화량이라는 점도 짚어주세요.

기준 실험에서는 밝기 ±20%를 추가했을 때 정상 오검률이 98%가 됐습니다.
모델이 낯선 촬영 조건을 실제 불량과 혼동할 수 있다는 예시입니다.
작은 회전에서는 오히려 점수가 낮아졌는데, 보간의 영향은 가능한 설명이며 아직 확정된 원인은 아닙니다.

함께 확인할 질문: “이 모델을 개선하려면 다음 실험에서 무엇을 한 가지 바꿔보고 싶나요?”

## 이미지 한 장을 함께 판정해 보기

기본 실행을 완료했다면:

```bash
python -m src.inference data/test/anomaly/scratch_0000.png
```

smoke test만 실행했다면 데이터와 모델 경로를 둘 다 smoke 결과로 지정합니다.

```bash
python -m src.inference outputs/smoke/data/test/anomaly/scratch_0000.png --model outputs/smoke/models/autoencoder.pt
```

출력의 `score`, `threshold`, `prediction`을 같이 읽습니다.
다른 사진도 넣어 보고 점수와 판정이 어떻게 달라지는지 비교하세요.
한 장을 맞힌 결과와 전체 test 성능은 구분해서 설명합니다.

## 설명할 때 혼동하기 쉬운 부분

- anomaly score는 불량 확률이 아닙니다.
- heatmap은 RGB 평균 절대 오차이고, 판정 점수는 MSE입니다.
- AUROC 0.82는 현재 임계값에서 정답률이 82%라는 뜻이 아닙니다.
- 추론 시간은 모델과 MSE 계산 범위입니다. 제조 라인의 전체 cycle time은 따로 측정해야 합니다.
- 같은 원본을 변형한 200장은 서로 독립적인 부품 200개가 아닙니다.

직접 수정해 보고 싶다면 [과제 6개](LEARNING_GUIDE.md#exercises) 중 하나를 골라
예상 결과를 먼저 적고, 실행 후 [실험 템플릿](EXPERIMENTS.md#template)으로 비교하면 좋습니다.
